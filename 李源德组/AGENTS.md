# 用户的 STM32/HAL 熟悉度与代码习惯

本文主要记录从现有 STM32 工程代码中观察到的用户能力与编码习惯，并保留可复用的注释协作和Keil验证方法；不作为某一个具体工程的外设配置或带功率验收标准。

## 综合熟悉程度

- 用户处于 **STM32/HAL 中级应用开发水平，偏电力电子控制与外设集成**。
- 相比底层驱动开发，用户更擅长把 CubeMX 生成的 HAL 工程、采样、PWM、控制算法和显示调试组合成可运行的应用。
- 控制算法与功率变换应用知识明显强于嵌入式软件架构、并发模型和底层寄存器优化。
- 用户已经越过 GPIO、串口、定时器等入门阶段，可以直接讨论外设参数、控制周期、采样值、调制度和闭环结构。
- 当前代码尚未表现出系统使用 LL、直接寄存器、RTOS、复杂 DMA 回调、低功耗模式或高级故障诊断的习惯。

## 分领域熟悉程度

| 领域 | 当前表现出的程度 | 代码中的表现 |
| --- | --- | --- |
| CubeMX 与 Keil | 中等熟练 | 使用 CubeMX 生成工程，在 Keil 中组织用户模块和 CMSIS-DSP 库 |
| HAL 基础使用 | 中等熟练 | 能初始化并启动 ADC、DMA、TIM、PWM、UART，使用 HAL 回调和 HAL 宏 |
| 定时器与 PWM | 中等熟练 | 使用基本定时器形成固定控制节拍，使用高级定时器中心对齐 PWM 并动态更新 CCR |
| ADC 与 DMA | 中等应用水平 | 使用多通道规则组、外部触发和循环 DMA，将采样值送入测量与控制代码 |
| UART 与显示 | 基础到中等 | 使用阻塞式 UART 发送、VOFA 浮点帧和 OLED 显示进行调试 |
| 数字控制算法 | 中等偏强 | 能实现增量式 PI、QPR、双环控制、限幅、软启动与正弦参考生成 |
| CMSIS-DSP | 基础应用水平 | 会调用现成的 arm_rms_f32()，尚未表现出更广泛的 DSP 优化习惯 |
| 中断与实时性 | 初中级 | 会把周期控制放入 HAL 定时器回调，但代码组织仍偏功能优先，实时预算意识尚未完全体系化 |
| DMA/ISR 并发 | 初中级 | 理解 DMA 自动搬运和共享采样数组，但共享数据声明、一致性和所有权处理不够统一 |
| LL/寄存器开发 | 暂无充分证据 | 主要使用 HAL API 和 __HAL_* 宏，没有形成直接寄存器驱动风格 |
| 软件工程化 | 初中级 | 已按功能拆分 .c/.h，但仍大量使用全局状态、硬编码参数和保留的试验代码 |

## 总体编码风格

- 采用 **CubeMX 生成框架加用户功能模块** 的方式开发，保留 USER CODE BEGIN/END 区域。
- 偏好裸机前后台结构：高频控制放定时器回调，显示与调试放主循环。
- 以“先跑通功能、再逐步调参与替换”为主要迭代方式，代码中会保留旧方案和备用方案的注释。
- 喜欢用中文注释解释硬件用途、物理意义和调参意图，并使用长横线或等号分隔功能区。
- 注释侧重“这段代码做什么”和“参数大致如何调整”，较少描述并发所有权、边界条件、调用约束和设计原因。
- 命名混合模块英文缩写、物理量符号和个人前缀，例如 U_fb、I_ref、AC_rms、hhSerialSendByte()。
- 偏好直观的全局变量和 extern 在模块间共享数据，较少使用统一上下文对象或严格封装的接口。
- 常量同时使用宏、文件级 const 和函数内局部 const；更关注调参方便，参数归属尚未完全统一。
- 代码排版以可读和快速修改为主，缩进、空行、花括号风格及中英文编码并不完全统一。

## 代码注释协作规范

- 后续为用户代码补充注释时，应参考 `pfc_measure.c` 的组织方式：先在 `.c` 文件顶部说明模块“负责什么、不负责什么”，再用简短数据流描述输入、处理过程和输出；涉及缩写信号时，同时写明物理意义和单位。
- 注释详略按用户的 STM32/HAL 中级水平编写。可以直接使用 ADC Rank、DMA Circular、ISR、HRTIM Master、Compare、Preload、Dead Time、Fault 等术语，不需要解释普通变量赋值、`if`、GPIO 高低电平或常规 HAL 句柄语法。
- 用户已经手动写好且含义正确的注释应原样保留。不要仅为统一措辞而重写；只在缺少单位、数据所有权、调用约束或安全边界时，在相邻位置补充内容。
- 文件级注释应优先说明模块边界和数据流。例如测量模块说明 `HRTIM Trigger -> ADC -> DMA -> 同步快照 -> 控制/主循环`，PWM模块说明 `调制指令 -> Compare预装载 -> 周期边界生效 -> 输出`。不要让读者仅凭函数名猜测跨模块关系。
- 变量注释优先写明物理意义、单位、合法范围、更新时间和所有权。相关变量可以采用分组注释，避免对一眼可知的临时量逐行复述；但DMA缓冲区、序列号、心跳、故障位、零点累加器和跨ISR共享状态必须明确“谁写、谁读、何时有效”。
- 参数宏和标定系数应说明单位、计算来源和调整条件。占位参数必须明确写成“低压测试占位值”或“需要按板级参数重新计算”，不能让临时比例、死区或保护阈值看起来像最终设计值。
- 公共函数使用可被编辑器关联的 Doxygen 注释，至少按需要包含 `@brief`、`@param`、`@retval` 和 `@note`。`@note`重点说明调用位置（初始化、主循环或ISR）、是否允许阻塞、前置条件、失败行为以及是否会操作PWM、Gate Enable或故障状态。
- `.h`中的注释描述公共接口契约、参数单位、返回值和调用限制；`.c`中的注释描述实现数据流、关键中间量和硬件副作用。静态辅助函数只需说明计算目的、输入输出和特殊边界，不必复制公共接口的整段说明。
- DMA与ISR相关注释必须区分DMA原始数组和已经发布的一致性快照，解释使用 `volatile` 的原因、同步序列或心跳如何推进，以及临界区如何保证结构体复制不会读到半更新数据。不能把 `volatile` 描述成原子性或线程安全保证。
- HRTIM相关注释应明确Master与子定时器的分工、占空比到Compare的映射方向、预装载值在哪个更新边界生效，以及“计数器已启动”“MCU PWM引脚已开放”“Gate Enable已使能”是三个不同状态。
- 保护代码应区分硬件即时关断和软件记录：驱动器DESAT/OCP或HRTIM Fault负责无CPU快速关闭输出，Fault ISR负责拉低使能、锁存故障和提供诊断。不要把ISR描述成短路保护的第一响应路径。
- 高频ISR中的浮点代码应注明其执行上下文和实时性要求。STM32G474可使用单精度FPU，但只有结合编译器FPU选项或反汇编证据才能断言实际生成硬件浮点指令；同时应注意ISR首次使用FPU可能增加上下文保存开销。
- 注释必须与当前 `.ioc`、生成代码和实际调用关系一致。未验证的引脚复用、Fault路由、更新边界或FPU设置应写成“需要核对/实测”，不能仅根据设计意图写成已经成立的事实。
- 仅执行“补注释”任务时，不得顺带修改变量声明、常量、接口、控制逻辑或CubeMX生成配置。完成后应检查注释定界符、UTF-8编码、USER CODE标记和 `git diff --check`；无法使用Keil编译时要明确说明验证边界。

## 固件修改配套Markdown说明规范

- 后续每次修改STM32工程的`.c`或`.h`代码时，都必须在同一工程中同步新建或更新一份项目级Markdown说明文件，内容和详略参考`三相逆变开环工作流程与验证注意事项.md`。这项工作属于代码任务的固定交付内容，不需要用户每次重复提出。
- 配套说明按“一次工程功能修改对应一份项目级文档”组织，不为每个`.c`或`.h`机械新建一份文档。工程中已经存在`工作流程与验证注意事项.md`时应直接更新；只有不存在合适文档时，才在工程根目录新建`<功能名称>工作流程与验证注意事项.md`，避免产生内容相互矛盾的副本。
- 即使本次只修改注释或调试代码，也要复核配套说明是否仍与代码一致。若执行行为没有改变，应在验证记录中明确写明“本次未改变运行流程/硬件行为”，不应虚构新的功能变化。
- 编写配套说明前，应按“实际原理图和已焊接板卡 -> 当前`.ioc`及CubeMX生成初始化 -> 当前源代码调用关系 -> 旧Markdown/计划文档”的顺序建立事实。发生冲突时以前三项为准，并在文档中标出旧说明已经过期或仍需实测确认。
- 文档只能写入当前代码和硬件真实具备的能力。未接线的HRTIM Fault、未贴装器件、备选隔离放大器、宽窗口AWD、没有返回信号的驱动保护，以及只存在于原理图预留中的功能，必须标记为“预留/未验证/当前不构成保护”，不能写成已生效。
- 配套说明至少包含以下内容，并按工程实际删减无关章节：
  1. 本次功能目标、适用固件版本、修改文件和明确未修改的文件。
  2. 实际使用的系统板、驱动板、功率板和采样板，以及板间电源、地、PWM、ADC和Fault连接关系。
  3. 从复位、外设初始化、ADC校准、DMA/HRTIM启动到开放PWM或进入闭环的完整状态流程。
  4. 高频ISR/回调的数据流、运行频率、数据所有权、快照机制和禁止的阻塞操作。
  5. PWM频率、调制度、占空比、Compare反向/正向映射、死区及预装载生效边界；参数变化时给出必要公式和典型数值。
  6. ADC引脚、Rank、DMA下标、物理信号、零输入电压/原始码、极性、量程、标定方法和当前占位参数。
  7. OLED、VOFA和Keil Watch的通道定义、正常反应、刷新周期及调试器暂停CPU的影响。
  8. 按“无功率采样 -> MCU PWM -> 驱动无母线 -> 低压限流带功率 -> 闭环”的分阶段验证步骤和每阶段准入条件。
  9. 故障码表和“现象 -> 可能原因 -> 定位步骤 -> 处理方法”异常排查表，覆盖ADC贴轨、DMA失步、Fault、IWDG复位、OLED闪烁、VOFA中断、PWM测频误判和功率器件异常。
  10. 当前保护能力、缺失的硬件保护、示波器接地风险、限流要求、禁止升压条件和故障后恢复规则。
  11. 后续修改输入电压、输出RMS、30/60 Hz、采样比例或闭环参数时需要同步重算和重新验收的项目。
- 调制度不能直接写成固定占空比。对SPWM/CBSVPWM/HRTIM项目，应根据当前算法写明`调制度 -> 零序注入后的桥臂调制量 -> duty -> Compare`关系，并至少列出软启动起点、50%进度和稳态的理论占空比范围；最终值必须注明死区和驱动传播延时会带来偏差。
- ADC说明必须依据具体采样板，不得套用统一的“零输入约2048”。偏置双极性信号应写明中点；单极性母线电压零输入可能接近0；带可调VREF或反相调理的通道必须写明实测标定步骤。
- 修改完成后，应同时检查代码和Markdown的UTF-8、相对路径、表格、代码块、故障码和参数一致性。能够构建时记录Keil错误/警告和关键镜像信息；无法构建或无法上板时，明确写出只完成了哪些静态验证，不得把静态检查表述为上板通过。
- 交付时需要在最终答复中给出配套Markdown的绝对路径，并简要说明本次根据哪些板卡更新了哪些运行流程、保护边界和异常处理内容。

## 当前项目板卡事实与使用边界

以下板卡是后续单相PWM整流器、三相逆变器及联合工程说明的默认硬件背景。每次仍需结合当前接线、`.ioc`和实物贴装状态复核，不能只凭本节推断全部功能已经接通。

### STM32G474系统板扩展板

- 系统板负责把STM32G474的HRTIM、ADC、USART、OLED和预留Fault等引脚引出到独立连接器。
- 三相逆变当前使用PB12/PB13、PB14/PB15、PC8/PC9作为HRTIM C/D/E六路PWM；单相整流器使用A/B桥臂。HRTIM F和第4桥臂只有在任务明确要求时才能启用。
- ADC连接关系必须同时核对系统板连接器、采样板输出、`.ioc` Rank和DMA数组，不能仅凭网络命名判断相序。
- PB10是HRTIM1_FLT3预留入口；只有实物确实接入低有效故障源并完成无CPU关断测试后，才能计入自动硬件保护链。

### UCC21520 MOSFET驱动板

- 每块驱动板使用UCC21520双通道隔离驱动，逻辑侧需要+5 V/DGND，隔离输出电源由+12 V输入产生，PWMA/PWMB分别驱动一个半桥的上、下管通道。
- 当前原理图中`DISABLE`固定为低，板上没有由MCU控制的独立Gate Enable；因此HRTIM PWM引脚一旦开放，驱动板会立即响应。
- 当前驱动板没有提供给MCU的nFAULT、DESAT或OCP返回信号。软件Fault、ADC AWD和T5A保险丝都不能替代微秒级MOSFET短路/直通保护。
- HRTIM死区与驱动板DT网络、传播延时和门极器件共同决定实测死区。高侧门极必须按Gate-Source用差分/隔离探头测量，禁止把普通示波器地夹接到浮动开关节点。

### 三相四线功率板

- 功率板包含四个MOSFET半桥、直流母线电容、每桥臂470 uH输出电感及T5A输入保险丝。当前三相三线逆变只使用三个桥臂，第四桥臂和中性点保持断开。
- 三相三线固件必须调用三桥臂算法并保持HRTIM F关闭；不能因硬件存在第4桥臂就默认使用三相四线控制。
- T5A保险丝只能处理持续严重故障或线缆级保护，不能视为MOSFET直通保护。首次带功率必须使用5 V限流电源和对称阻性负载。

### 三相交流采样板

- 该板用于逆变器三相电流和三路线电压采样，+5 V输入经板上稳压得到3.3 V，并使用缓冲后的`1V65REF`作为双极性交流信号中点。
- `CURROUT1/2/3`对应IU/IV/IW，`VOLOUT1/2/3`在当前三相三线工程中对应VUV/VVW/VWU；零输入时六路应接近1.65 V，即12位ADC约2048，但各通道仍需分别做offset标定。
- 电压通道原理图按约29/36 V RMS量程设计，2.5 V RMS低压开环时ADC交流摆幅可能较小。此阶段用于验证通道、相序和趋势，不能直接宣称达到最终测量精度。
- 三路线电压输入必须按U-V、V-W、W-U统一极性接线；完成比例和极性标定后，`IU+IV+IW`及`VUV+VVW+VWU`才可作为一致性诊断量。

### 直流耦合采样板

- 该板是单相PWM整流器使用的补充采样板，提供`CURROUT`、`VOLTOUT`和`BIESVOLT`输出。后续PFC代码和说明应优先依据该板，而不是套用三相交流采样板的零点和量程。
- 板上输入8～12 V，经HR1117V-5.0得到+5 V，并经AMS1117-3.3得到+3.3 V；上板前需分别验证两路电源。
- 电流通道原理图标注`VACS = 2.5 V + 0.185 V/A * I`，经MCP6002调理后，`CURROUT`标注典型值为：-5 A约3.10 V、0 A约1.675 V、+5 A约0.25 V。该通道极性为电流增加时ADC电压降低，代码不得擅自在PR/PI内部隐藏反号，应在标定或测量层明确处理。
- `VOLTOUT`来自直流输入经150 kΩ及50 kΩ可调分压、MCP6002缓冲和RC滤波后的单极性电压。其零输入通常接近0，而不是1.65 V；实际V/count比例由电位器位置、器件误差和实测输入共同确定。
- `BIESVOLT`由可调`VREF`和`VOLTOUT`经过MCP6002调理得到，适合需要偏置的电压采样路径。其零点、极性和增益必须同时测量`VREF`、`VOLTOUT`和`BIESVOLT`后确认，不能仅按元件标称推断。
- 原理图底部的AMC1301/AMC1350/AMC1200/AMC1300属于隔离采样器件备选展示；除非实物确认已经贴装并接入当前信号链，否则不得宣称`CURROUT/VOLTOUT/BIESVOLT`具备这些器件提供的隔离能力。
- `CURROUT`、`VOLTOUT`、`BIESVOLT`与IPFC、VBUS、VAC的最终映射必须以实物接线、系统板引脚和`.ioc` Rank共同确认。未确认前只能写成候选对应关系，不能把网络名称直接当作已验证的软件映射。

## 本次PFC注释完善实践总结

- 注释任务开始前先固定修改边界：本次只处理 `main.c`、PFC应用模块及对应头文件，不修改 `.ioc`、CubeMX生成的外设初始化、参数值、声明、接口和控制逻辑。先记录受保护文件SHA-256并完成一次基线构建，便于修改后证明边界没有被突破。
- Windows PowerShell读取中文源文件时应显式使用 `Get-Content -Encoding UTF8`。终端默认编码可能把正常中文显示成乱码；在没有按UTF-8重新读取前，不能据此判断源文件损坏，更不能贸然批量转码。
- 审查顺序应从跨模块逻辑开始，而不是逐行添加解释：先确认模块职责和数据流，再清点文件级变量、共享状态、公共函数、静态辅助函数和HAL回调，最后补局部物理量、单位与边界。这样更容易发现“注释存在但含义已经过期”的问题。
- 本次确认了以下容易误导的注释并完成修正：VOFA当前没有测试锯齿且标定/运行模式的通道定义不同；OLED不能列出代码尚未实现的欠压、过温和驱动故障；ADC2 DMA负责写VAC原始数组，ADC2完整回调只推进序列号；`PFC_HRTIM_OutputsEnabled()`是软件命令镜像，不是引脚或功率管状态回读；当前SPWM是VAC同步开环前馈，不是IPFC电流闭环，也不能宣称9 V精密稳压。
- 对DMA/ISR状态的注释应落到所有权：DMA写原始数组，ADC2 ISR发布VAC序列，ADC1 ISR核对序列并发布测量快照，主循环通过临界区接口取得副本。`volatile`只要求编译器执行实际内存访问，不提供跨数组同步、结构体原子性或线程安全。
- 对HRTIM保护的注释应落到响应先后：HRTIM Fault硬件先把输出置为Inactive，Fault ISR随后锁存软件故障并提供诊断；计数器运行、PWM引脚开放和外部驱动实际工作不能合并描述。当前板卡没有MCU Gate Enable时，更要明确开放HRTIM输出就是软件功率许可边界。
- 参数注释不能只写字段名称。本次按参数档逐组标明V RMS、V peak、Hz、H、F、A peak、A/s和count等单位，并明确5 V及36 V档的ADC比例、零点和极性仍是占位值；`calibration_valid=0`时只能运行ADC/DMA、OLED和VOFA标定路径。
- 注释完成后应使用搜索脚本确认每个函数定义前存在文档块，并检查过期关键词、注释定界符数量、UTF-8有效性和CubeMX `USER CODE BEGIN/END`数量。本次 `main.c` 的USER CODE标记保持为17组，目标文件通过 `git diff --check`，只出现现有LF/CRLF提示，没有空白错误。
- 本次最终覆盖6个应用 `.c` 和5个对应 `.h`，Keil构建保持 `0 Error(s), 0 Warning(s)`；纯固件二进制SHA-256在修改前后均为 `6EA640A15BD73EEAF596C5353B12A04B00EAED802E0D00A58A0117292A9F9C01`，证明注释调整没有改变处理器执行的程序和常量数据。

## HRTIM 熟悉程度与协作方式

- 根据 `Xiaosai3.0.ioc`，用户对 STM32G4 HRTIM 处于 **基础到中等应用熟悉度**：已经能在 CubeMX 中独立建立单个 HRTIM 子定时器的双路 PWM，但尚无充分证据表明已经掌握数字电源所需的完整同步、采样触发和硬件保护链路。
- 用户能够把 HRTIM Timer B 的 TB1/TB2 映射到 PA10/PA11，说明已理解 HRTIM 子定时器、输出通道和物理引脚复用之间的基本对应关系。
- 用户已配置上下计数模式、周期 `60000`、比较值 `30000`、`MUL16` 时基、比较单元 1 和输出预装载，说明能够使用 CubeMX 形成中心对称 PWM 的基础时基与占空比关系。
- 用户已启用 TB1/TB2 死区插入，并为上升沿、下降沿分别填写 `100`，说明知道互补功率桥需要死区，也能找到 CubeMX 中对应配置入口；当前文件不能证明其已经完成死区时钟换算或根据驱动器、功率器件实测确定最终死区。
- 用户已选择重复周期更新和 Timer B Repetition Interrupt，并启用 HRTIM1_TIMB NVIC，说明理解预装载参数需要在确定的周期边界生效，也知道可使用 HRTIM 周期事件形成软件控制节拍。
- 当前配置只使用 Timer B，没有体现 Master Timer、Timer A/C/D/E/F、多子定时器同步或跨桥臂原子更新，因此后续涉及单相全桥 A/B 或三相多桥臂时，应明确解释 Master 周期、Reset/Update Source 和同步更新关系。
- `ADCTrigger_Id1=__NULL`，当前没有配置 HRTIM 触发 ADC。后续指导同步采样时，需要从“选择哪个 HRTIM 比较/周期事件作为 ADC Trigger、为什么该位置是 PWM 安静窗口、如何确认每周期只执行一次控制”开始讲解，不能假设用户已经熟悉 HRTIM-ADC 触发矩阵。
- 当前配置没有体现 HRTIM Fault 输入、Fault 极性、滤波、锁存或输出故障态。后续功率项目必须完整说明外部驱动器 `nFAULT/DESAT/OCP -> HRTIM Fault -> PWM 无效态` 的硬件路径，并区分硬件即时关断与 Fault ISR 的软件记录职责。
- 当前 TB1 的 Set Source 使用 Compare 1，而 Reset Source 为 None，输出行为还需结合 Output ROM、互补输出和实测波形核对。后续分析 `.ioc` 时应检查 Set/Reset 事件是否闭合、TB1/TB2 是否真正互补、周期边界是否会恢复到预期状态，不能只根据“已启用两个输出”判断波形正确。
- 后续与用户讨论 HRTIM 时，可以直接使用 Period、Compare、Preload、Dead Time、Repetition、Set/Reset Source 等 CubeMX 术语，不必从普通 GPIO 或基本 PWM 概念讲起；但对 HRTIM 高分辨率时钟倍率、上下计数频率公式、Master/子定时器同步、ADC Trigger、Fault 锁存和输出状态表应给出计算过程与示波器验收方法。
- 对用户 HRTIM 能力的描述应以实际 `.ioc`、生成的 `MX_HRTIM1_Init()` 和示波器结果为证据。未配置的功能只能写成“尚无充分证据”或“需要补充”，不能直接推断用户不会使用。

# STM32G474 固定硬件条件下的保护外设配置方案

## 1. 文档结论

本方案面向已经定型的板卡，在不改PCB的前提下，尽可能利用 STM32G474 的 HRTIM、ADC模拟看门狗、COMP、CSS 和 IWDG 完成单相PWM整流器与三相三线逆变器的保护和控制。最终联合工程以：

`01仅INV/02仅INV初步开环/02OpenLoop.ioc`

为配置基线。单相专用的 `03-1OpenLoop.ioc` 只用于PFC分模块调试，不再作为最终联合运行工程的起点。

现有硬件存在一个不能由CubeMX或软件消除的边界：驱动板的 UCC21520 `DISABLE` 固定接低，且没有引出 `nFAULT`、DESAT 或 OCP。由此可知：

- `PE0/PE1`没有接到驱动器，不能称为有效的Gate Enable；
- `PE5/PE6`没有实际故障源，不能称为驱动器故障输入；
- `PB10/HRTIM1_FLT3`有上拉和扩展接口，但目前没有自动故障源；
- MCU仍可通过停止HRTIM PWM命令关断功率管，但不存在独立于MCU和采样链的半导体短路保护。

因此，本方案能显著增强过流、过压、欠压、采样失步、时钟异常和软件失控保护，但不能把现有系统提升为具备DESAT/OCP的硬件短路保护系统。高压或大电流运行仍必须使用限流电源、快速熔断器和外部急停。

## 2. 保护分层

| 层级 | 信号路径 | 典型响应 | 是否依赖CPU | 本项目作用 |
| --- | --- | --- | --- | --- |
| L0 板级被动保护 | 熔断器、驱动器UVLO、栅极下拉 | 由器件决定 | 否 | 保留现有硬件能力 |
| L1 HRTIM硬件Fault | PB10低电平 -> FLT3 -> A~E输出Inactive | HRTIM硬件级 | 否 | 手动急停和故障注入 |
| L1增强COMP | 电流/母线采样 -> COMP -> 内部Fault或COMP IRQ | 快于10 kHz ADC节拍 | 内部Fault不依赖，IRQ依赖 | 有限的单方向快速阈值保护 |
| L2 ADC模拟看门狗 | ADC转换结果越过上下限 -> ADC IRQ -> 停PWM | 最坏约一个100 us采样周期加ISR延迟 | 是 | 全通道窗口保护 |
| L3 快速软件保护 | DMA同步快照 -> 标定/范围/一致性检查 | 10 kHz | 是 | 过流、过压、采样失步 |
| L4 安全监督 | 心跳、状态机、DMA、Fault、CSS、IWDG | 1~500 ms | 是 | 软件卡死和状态异常复位 |

ADC看门狗和10 kHz软件保护属于过载保护，不能代替MOSFET短路保护。三相采样板输出端约 `1 kOhm + 100 nF` 的滤波也会增加信号延迟。

## 3. 最终保留、增加和删除项

### 3.1 必须保留

| 外设 | 最终用途 | 配置结论 |
| --- | --- | --- |
| HRTIM Master/A~E | PFC两桥臂和逆变三桥臂 | 保持现有10 kHz中心对齐配置 |
| HRTIM FLT3/PB10 | 手动急停、故障注入 | 保持低有效、无Blanking、作用于A~E |
| ADC1~5 + 五路DMA | 五路电流/电压同步采样 | 保持规则组、循环DMA和HRTIM触发 |
| ADC模拟看门狗 | 电流、电压上下限 | 新增，覆盖各ADC现有通道 |
| RCC CSS | HSE失效检测 | 保持启用，NMI必须安全关断 |
| IWDG | 软件和控制心跳监督 | 保持约500 ms，最后初始化 |
| USART2/OLED | 低速诊断 | 保留，只能在主循环使用 |

### 3.2 建议增加，但必须先无功率验证

| 外设 | 使用信号 | 结论 |
| --- | --- | --- |
| COMP1 + DAC1 CH1 | PA1/IPFC | 可做一个方向的快速PFC电流阈值 |
| COMP4 + DAC3 CH2 | PB0/IU | 可做一个方向的快速U相电流阈值 |
| COMP3 + DAC3 CH1 | PC1/VBUS | 可做母线过压快速比较，但FLT3已被PB10占用，建议先仅用COMP IRQ |

同一模拟引脚同时供ADC和COMP使用在芯片内部是可行的，但CubeMX可能把同一物理引脚显示为复用冲突。若CubeMX不能同时分配，不得取消ADC；应保留ADC引脚配置，在生成代码的USER CODE中手动初始化COMP，并逐项核对GPIO仍为Analog、无上下拉。该增强层只有在示波器和故障注入验证通过后才允许参与带功率关断。

### 3.3 应取消原有保护含义

| 当前名称 | 实际硬件情况 | 最终处理 |
| --- | --- | --- |
| `PFC_GATE_EN/PE0` | 未接驱动器 | 保持输出Low，可改名为预留GPIO，不作为启动条件 |
| `INV_GATE_EN/PE1` | 未接驱动器 | 保持输出Low，可改名为预留GPIO，不作为启动条件 |
| `PFC_NFAULT_DIAG/PE5` | 无实际故障源 | 取消EXTI；改为普通输入/预留，或明确接按钮后再启用 |
| `INV_NFAULT_DIAG/PE6` | 无实际故障源 | 取消EXTI；改为普通输入/预留，或明确接按钮后再启用 |
| `PRECHARGE_EN/PE2` | 仅扩展接口 | 未接继电器时保持Low，不得假设预充有效 |
| `DISCHARGE_EN/PE3` | 仅扩展接口 | 未接放电器件时保持Low，不得假设主动放电有效 |

如果允许使用现有扩展连接器和跳线，优先把一个常闭急停按钮接在 `PB10-GND` 之间。PB10已有约10 kOhm上拉，断线或按钮状态仍须在每次上电自检中读取确认。不要把普通按钮接到PE5/PE6后称为驱动器OCP。

## 5. HRTIM Fault配置

### 5.1 PB10手动急停

| CubeMX位置 | 字段 | 设置值 | 生成代码核对 |
| --- | --- | --- | --- |
| Pinout | PB10 | `HRTIM1_FLT3` | GPIO为HRTIM Fault输入 |
| HRTIM > Fault Configuration | Fault Line 3 Source | `Digital Input` | `HRTIM_FAULTSOURCE_DIGITALINPUT` |
| 同上 | Polarity | `Active Low` | `HRTIM_FAULTPOLARITY_LOW` |
| 同上 | Filter | `None` | 首轮保留当前设置 |
| 同上 | Blanking | `None` | 不允许屏蔽急停 |
| 同上 | Lock | Read/Write | 调试完成前不锁配置 |
| HRTIM Timer A~E | Fault Enable | `Fault 3` | 五个Timer均包含`HRTIM_TIMFAULTENABLE_FAULT3` |
| Output A1~E2 | Fault Level | `Inactive` | 十路输出均为Inactive |
| NVIC | HRTIM1 Master/Fault | Preemption 0 | `HRTIM1_FLT_IRQn`优先级0 |

FLT3触发后禁止自动恢复。软件只能在母线放电、操作者确认、故障输入恢复且重新执行自检后，进行显式故障复位和重新启动。

### 5.2 COMP内部Fault增强

建议先配置：

- `COMP1 -> HRTIM Fault 1 -> Timer A/B`，只关断PFC；
- `COMP4 -> HRTIM Fault 4 -> Timer C/D/E`，只关断逆变器；
- 任意分区Fault ISR随后停止A~E全部输出，使系统进入联合故障锁存。

在CubeMX的HRTIM Fault页中，只有当所用版本明确显示相应内部比较器来源时，才把Fault 1/4的 `Source` 设为 `Internal`。生成代码必须看到：

```c
pFaultCfg.Source = HRTIM_FAULTSOURCE_INTERNAL;
```

并通过改变比较器输入确认对应 `FLT1/FLT4` 标志和目标PWM确实在无CPU参与时变为Inactive。若CubeMX没有给出正确内部路由，或测试中只能进入COMP中断而HRTIM输出未立即关闭，则不得把它登记为L1硬件保护，只能降级为COMP IRQ软件关断。

不建议为COMP使用PWM边沿Blanking作为第一版配置。先使用 `Blanking Source = None`，观察实际噪声误触发；只有确定误触发来自固定开关沿后，才配置与该桥臂同步的窄Blanking窗口。Blanking过宽会遮蔽真实过流。

## 6. ADC规则组和模拟看门狗

### 6.1 现有采样序列

| ADC | Rank 1 | Rank 2 | 触发 |
| --- | --- | --- | --- |
| ADC1 | PA1/IPFC | PC1/VBUS | HRTIM Trigger 1 |
| ADC2 | PC0/VAC | 无 | HRTIM Trigger 1 |
| ADC3 | PB0/IU | PD10/VUV | HRTIM Trigger 2 |
| ADC4 | PD8/IV | PE14/VVW | HRTIM Trigger 2 |
| ADC5 | PD9/IW | PD14/VWU | HRTIM Trigger 2 |

三相输出为三相三线，Rank 2采样量应统一称为线电压 `VUV/VVW/VWU`，不应写成相对中性点的 `VU/VV/VW`。

### 6.2 推荐看门狗分配

每个ADC可使用Analog Watchdog 1监视Rank 1，并用Analog Watchdog 2监视Rank 2。ADC2只有VAC，因此仅使用一个窗口。

| ADC | Watchdog | 监视频道 | 阈值类型 | 越界动作 |
| --- | --- | --- | --- | --- |
| ADC1 | AWD1 | IPFC | 双向过流上下限 | 关闭A~E并锁存PFC过流 |
| ADC1 | AWD2 | VBUS | 母线过压/欠压窗口 | 过压立即停机；欠压按运行状态判定 |
| ADC2 | AWD1 | VAC | 输入过压/输入丢失窗口 | 过压停机；丢失按持续时间停机 |
| ADC3 | AWD1 | IU | 双向过流上下限 | 关闭A~E并锁存U相过流 |
| ADC3 | AWD2 | VUV | 线电压粗略上下限 | 仅运行态启用有效窗口 |
| ADC4 | AWD1 | IV | 双向过流上下限 | 关闭A~E并锁存V相过流 |
| ADC4 | AWD2 | VVW | 线电压粗略上下限 | 仅运行态启用有效窗口 |
| ADC5 | AWD1 | IW | 双向过流上下限 | 关闭A~E并锁存W相过流 |
| ADC5 | AWD2 | VWU | 线电压粗略上下限 | 仅运行态启用有效窗口 |

CubeMX字段名称会随ADC页面布局略有差异，目标配置必须对应以下HAL语义：

| 字段 | 设置 |
| --- | --- |
| Watchdog Mode | Single regular channel或channel mask |
| Channel | 对应ADC Channel，不使用Rank编号代替Channel |
| IT Mode | Enable |
| High Threshold | 标定得到的高端ADC码 |
| Low Threshold | 标定得到的低端ADC码 |
| Filtering/Number of samples | 首轮1次；噪声实测后再增加 |

ADC模拟看门狗配置最终应调用 `HAL_ADC_AnalogWDGConfig()`。ADC1/2共享 `ADC1_2_IRQn`，ADC3、ADC4、ADC5分别使用各自ADC IRQ；这些IRQ建议统一设为抢占优先级1。

### 6.3 阈值不能直接照抄固定数字

必须先用万用表、可调电源和已知负载标定每个通道。按电压直接换算时：

```text
ADC_code = round(Vadc / VDDA x 4095)
```

按电流的实测线性模型换算时：

```text
ADC_code(Itrip) = round(offset_code + slope_code_per_A x Itrip)
low_code  = min(ADC_code(+Itrip), ADC_code(-Itrip))
high_code = max(ADC_code(+Itrip), ADC_code(-Itrip))
```

PFC电流采样已知具有“电流增大、采样电压降低”的极性，因此不能默认 `+Itrip` 对应High Threshold。上下限必须由上式分别计算。阈值应留出ADC误差、运放偏移、纹波和过渡过程余量。

母线欠压、VAC丢失和线电压欠压不能在上电自检或软启动阶段直接作为硬故障，否则系统永远无法启动。建议：

- 过流和母线过压从开放PWM前即启用；
- 输入/输出欠压在进入相应运行状态并经过消隐计时后启用；
- 线电压AWD只作严重异常的粗保护，精确RMS、频率和不平衡判断放在软件窗口内完成。

### 6.4 AWD中断处理边界

ADC IRQ中只允许执行：

1. 读取并记录AWD来源；
2. 立即调用统一Trip入口停止A~E输出；
3. 锁存故障位；
4. 禁止继续刷新IWDG。

不得在ADC IRQ中使用OLED、阻塞USART、浮点RMS或复杂状态机。看门狗标志清除后也不得自动恢复PWM。

## 7. COMP/DAC增强配置

### 7.1 推荐通道

| 比较器 | 正输入 | 负输入 | 极性/用途 | 保护边界 |
| --- | --- | --- | --- | --- |
| COMP1 | `COMP_INPUT_PLUS_IO1` = PA1/IPFC | DAC1 CH1 | 根据IPFC传感器极性选择 | 只能覆盖一个电流方向 |
| COMP4 | `COMP_INPUT_PLUS_IO1` = PB0/IU | DAC3 CH2 | 根据IU传感器极性选择 | 只能覆盖一个电流方向 |
| COMP3 | `COMP_INPUT_PLUS_IO2` = PC1/VBUS | DAC3 CH1 | Non-inverted，母线超过阈值时有效 | 建议先用COMP IRQ软件停机 |

公共建议值：

| CubeMX/COMP字段 | 初始设置 |
| --- | --- |
| Hysteresis | 10 mV，实测后调整 |
| Output Polarity | 按故障时输出有效的方向选择 |
| Blanking Source | None |
| Trigger Mode | Interrupt on fault edge；不使用双边沿自动恢复 |
| Lock | 调试阶段Disable，最终验证后再决定 |

DAC仅作内部阈值，不需要映射到外部引脚。DAC码换算：

```text
DAC_code = round(Vtrip / VDDA x 4095)
```

不要用固定的3.3 V代替实测VDDA。COMP和ADC若共用同一采样节点，必须确认开启COMP后ADC码值、零偏和噪声没有不可接受变化。

### 7.2 为什么不启用全部COMP

- `IV/PD8`和`IW/PD9`没有同脚COMP正输入，固定PCB条件下不能直接得到三相全覆盖；
- COMP1/4各只有一个阈值，只能监视带偏置双极性电流的一侧；
- 为全部电流方向增加比较器需要把采样信号通过现有连接器跳接至其它COMP输入，属于额外接线，不应假设已经存在；
- COMP3使用内部Fault 3会与PB10数字FLT3冲突，因此保留PB10，COMP3先走中断；
- 即使COMP全启用，采样运放和RC滤波仍在保护路径内，仍不等同于驱动器DESAT。

因此，最终基线应先完成全部ADC看门狗，再把COMP1/4/3作为增强配置逐个启用和验证，而不是一次性打开COMP1~7。

## 8. GPIO、CSS、IWDG与NVIC

### 8.1 GPIO

| 引脚 | 最终配置 | 说明 |
| --- | --- | --- |
| PB10 | HRTIM1_FLT3，Pull-up | 手动急停/故障注入 |
| PE0/PE1 | Output Push-Pull，初始Low | 未接驱动器，保持预留 |
| PE2/PE3 | Output Push-Pull，初始Low | 未接执行器时不得拉高 |
| PE5/PE6 | 普通输入或Analog/未配置 | 无故障源时删除EXTI，避免悬空误触发 |

如果PE5/PE6确实接入外部常闭触点，再配置为带确定上拉的下降沿EXTI，优先级3，并在文档和原理图网名中改为真实用途。

### 8.2 CSS

保持 `RCC.EnbaleCSS=true`。NMI中检测CSS标志后，必须先停止A~E输出并锁存时钟故障，再清除CSS标志；不得只进入默认死循环。CSS动作仍依赖CPU执行NMI，因此它不是HRTIM硬件Fault的替代物。

### 8.3 IWDG

保持：

- Clock Source：LSI；
- Prescaler：64；
- Reload：249；
- 名义超时约500 ms，实际以LSI误差为准；
- 从CubeMX自动初始化顺序中移除，在所有安全GPIO、ADC/DMA、HRTIM和故障状态建立后手动调用 `MX_IWDG_Init()`。

100 ms监督周期只有在以下条件全部满足时才调用 `HAL_IWDG_Refresh()`：五路DMA序列推进、快速控制心跳推进、无ADC/AWD/COMP/HRTIM Fault、状态机未超时、采样快照有效、PB10为非故障电平。故障后不再喂狗，让系统复位回到PWM关闭状态。

### 8.4 NVIC优先级

使用Priority Group 4：

| 中断 | 抢占优先级 | 用途 |
| --- | ---: | --- |
| HRTIM1 Master/Fault | 0 | FLT1/3/4记录和联合停机 |
| COMP1_2_3、COMP4_5_6 | 0 | COMP软件后备关断 |
| ADC1_2、ADC3、ADC4、ADC5 | 1 | AWD和ADC错误 |
| ADC/DMA控制完成入口 | 2 | 10 kHz测量快照和控制 |
| PE5/PE6 EXTI（仅接线后） | 3 | 低速诊断/外部触点 |
| SysTick | 15 | HAL时基和后台调度 |

DMA优先级与NVIC优先级是两个不同概念。DMA通道硬件Priority保持High，NVIC按上表设置。

## 9. 软件必须配合的安全顺序

### 9.1 启动

```text
复位
-> 立即把A~E输出保持关闭，PE0~PE3为Low
-> 读取复位原因和PB10
-> 初始化GPIO/DMA/HRTIM/ADC/COMP/USART
-> 校准ADC并启动五路DMA
-> 启动HRTIM计数器，仅产生ADC触发，不开放输出
-> 检查DMA同步、ADC范围、零偏和所有Fault
-> 配置并启用AWD/COMP保护
-> 将比较值置为安全的50%状态
-> 按PFC、母线、INV软启动状态机逐级开放PWM
-> 最后初始化IWDG
```

### 9.2 统一Trip

所有Fault、AWD、COMP、ADC/DMA错误、CSS和不可恢复HAL错误均进入同一个Trip入口：

```text
停止HRTIM A~E十路输出
-> PE0/PE1保持Low
-> 禁止新的Compare更新
-> 锁存首个故障原因和时间戳
-> 复位PI/PR/QPR/SVPWM状态
-> 禁止自动重启
-> 停止刷新IWDG
```

因为PE0/PE1未接驱动器，真正停止开关命令依赖HRTIM输出停止，代码不能只拉低PE0/PE1。

## 10. 分阶段实施

### P0：无功率保护验证

1. 保持母线断电和驱动电源断开，只观察MCU HRTIM引脚。
2. 验证PB10拉低后A~E全部变为Inactive，CPU停在断点时仍能关断。
3. 验证复位、HardFault、CSS测试和IWDG复位后PWM不会自动开放。
4. 删除无接线PE5/PE6的EXTI保护依赖。

### P1：ADC看门狗验证

1. 用受限0~3.3 V信号逐个改变六路ADC输入。
2. 先设置宽阈值，确认每个AWD只响应正确Channel。
3. 越界后确认A~E全部停止、故障锁存、IWDG停止刷新。
4. 完成电压、电流的物理标定后再写正式阈值。

### P2：COMP增强验证

1. 依次启用COMP1、COMP4、COMP3，不同时一次启用全部。
2. 检查同脚ADC的偏置、增益和噪声是否变化。
3. 验证COMP1/4是否真正经内部Fault无CPU关断指定桥臂。
4. 若只能触发COMP IRQ，文档和代码必须将其标记为CPU关断路径。
5. 验证噪声后再决定Hysteresis和是否需要窄Blanking。

### P3：5 V低压功率验证

1. 使用限流5 V直流源、对称阻性负载和串联熔断器。
2. 先单独PFC低压开环，再单独三相逆变开环，最后联合启动。
3. 故障注入顺序为PB10、各ADC越界、任一路DMA停止、CSS、IWDG。
4. 任何保护不能稳定重复关断时，不得提高母线电压。

### P4：赛题电压和负载

只有在预充/放电的实际执行器接线得到确认、全部采样完成标定、LC滤波器和保护阈值完成实测后，才进入36 V交流输入、约52~55 V母线和32 V RMS线电压测试。额定功率阶段必须额外确认保险丝、器件SOA、散热和驱动供电。

## 11. 最终CubeMX配置档

### 最终联合运行必须启用

- HRTIM Master、A~E、ADC Trigger 1/2；
- PB10/HRTIM1_FLT3，Fault 3作用于A~E；
- ADC1~5规则组与五路循环DMA；
- ADC1~5 Analog Watchdog及其ADC IRQ；
- RCC CSS；
- IWDG；
- USART2、SWD和软件I2C OLED；
- HRTIM F保持关闭，三相输出保持三相三线。

### 条件启用

- COMP1/COMP4及DAC阈值：完成同脚ADC和内部Fault路由验证后启用；
- COMP3：完成母线标定后先以COMP IRQ方式启用；
- PE5/PE6 EXTI：只有确有外部触点接线时启用；
- PE2/PE3：只有确有预充/放电执行器接线时使用。

### 不应启用或不应依赖

- HRTIM F和四桥臂/中性线控制；
- 无实际信号的PE5/PE6故障中断；
- 把PE0/PE1当作驱动器硬件使能；
- 把ADC 10 kHz看门狗或COMP采样支路称为DESAT/OCP；
- Fault、ADC或DMA异常后的自动重启。

## 12. 验收清单

- [ ] `02OpenLoop.ioc`作为联合工程基线，A~E保持10 kHz中心对齐互补PWM。
- [ ] PB10低有效Fault 3在CPU暂停时仍能关闭A~E全部输出。
- [ ] PE0/PE1、PE5/PE6的文档名称与实际未接线状态一致。
- [ ] ADC1~5的Rank顺序与IPFC/VBUS/VAC/IU/IV/IW/VUV/VVW/VWU一致。
- [ ] 每个电流通道有双边ADC窗口，母线有过压和运行态欠压窗口。
- [ ] AWD中断不调用OLED、USART或复杂浮点运算。
- [ ] COMP1/4只有通过内部Fault实测后才登记为无CPU保护。
- [ ] 任意Fault、AWD、COMP或DMA失步均停止A~E并禁止自动恢复。
- [ ] CSS/NMI、HardFault和Error_Handler均先停止HRTIM输出。
- [ ] IWDG只在五路DMA、控制心跳、状态机和Fault全部健康时刷新。
- [ ] 所有阈值来自实测标定，不直接使用未经验证的固定ADC/DAC码。
- [ ] 5 V限流测试完整通过后才逐级提高母线和负载。

## 13. 最终安全边界

这份配置是在现有固定板卡上的最佳可实施方案，不是对硬件缺失DESAT/OCP的替代。若后续允许使用板间跳线，最有价值的改进顺序是：

1. 先把常闭急停接入PB10；
2. 再把各驱动分区的真实故障输出汇总到PB10，但当前驱动板没有该输出；
3. 再将IV/IW采样复制到空闲COMP输入，以补齐三相快速过流覆盖；
4. 最终仍应优先更换或增加带DESAT/OCP和可控DISABLE的驱动保护链。

在完成第4项之前，系统不得宣称具备独立硬件短路保护。
